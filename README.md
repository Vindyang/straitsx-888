# straitsx-888

Mandated agent payments on x402. An AI agent shops; a policy layer decides whether money is
allowed to move; a human holds a kill switch that lands on-chain within one block.

The load-bearing idea: **enforcement happens before signing.** The only moment of control is
the instant before the signature exists, because a signed EIP-3009 authorization is live in
the world whether or not anyone submits it.

Specs: [execution_plan.md](docs/execution_plan.md) · [api-contracts.md](docs/api-contracts.md)
· boards for [A](docs/owner-a-tasks.md) / [B](docs/owner-b-tasks.md) / [C](docs/owner-c-tasks.md)

## Setup

```bash
corepack enable
corepack pnpm install --frozen-lockfile
```

This is a pnpm workspace pinned to pnpm 10.33.0. `npm install dashboard` asks npm to install
an unrelated registry package named `dashboard`, while a standalone `npm install` inside
`services/dashboard` cannot resolve the repository's `workspace:*` dependency correctly.
Install once at the repository root as above, then either run
`corepack pnpm dev:dashboard` from the root or `npm run dev` from `services/dashboard`.

Foundry is needed only for the Solidity package. It installs to `~/.foundry/bin`, which is
**not** on PATH in a fresh shell:

```bash
curl -L https://foundry.paradigm.xyz | bash && foundryup
export PATH="$HOME/.foundry/bin:$PATH"
```

Copy `.env.example` to `.env`. The one value everyone needs is `INTERNAL_TOKEN` — every
service-to-service call carries it as `X-Internal-Token`, and services **fail closed**
without it, so a missing token shows up as `401` on every request.

## Module C AWS deployment

Module C deploys independently of A/B. Its process health stays green while authenticated
readiness and payment runs fail closed until the A/B owner connects the stable service
contracts. Use `scripts/publish-module-c-images.sh`, `scripts/deploy-module-c.sh`, and the
two-phase runbook in [docs/module-c-deployment.md](docs/module-c-deployment.md). Module C
does not create or modify A/B security-group rules.

Live-RPC tests are opt-in so CI stays green when Fuji is having a bad day. Run them before
every checkpoint — they are the only thing that re-proves the on-chain facts in
[§19.2](docs/execution_plan.md), and the Fuji XSGD contract is an upgradeable proxy whose
implementation can change mid-event.

The ABI lives in [`packages/contracts/registry.json`](packages/contracts/registry.json),
generated by `scripts/sync-registry.ts` from the `forge build` artefact — **never hand-edit
it.** The deployed bytecode was verified byte-identical to the local build, so the published
ABI provably describes the on-chain contract.

It adds three custom errors **not** in api-contracts §2, needed to decode reverts:
`MandateExists`, `NotOwner`, `AlreadyRevoked`.

**A redeploy gets a new address, and every mandate created against the old one becomes
unreadable.** `sync-registry.ts` warns on this; announce it immediately if it happens.

## Chain constants

| | Fuji 43113 | Mainnet 43114 |
| --- | --- | --- |
| RPC | `https://api.avax-test.network/ext/bc/C/rpc` | `https://api.avax.network/ext/bc/C/rpc` |
| XSGD | `0xd769410dc8772695a7f55a304d2125320a65c2a5` | `0xb2F85b7AB3c2b6f62DF06dE6aE7D09c010a5096E` |
| decimals | **6** — never 18 | **6** |
| EIP-712 `version` | `"2"`, from the 402 | **unknown — do NOT inherit `"2"`** |
| settlement recipient | `0x99a2B2962a6AC463FBe04664027Fdb3F68bd4Cc8` | `null` until the production 402 is fetched |

Paying wallet `0x9f6B4A5DE73CE365238F27236ea04A747E691bF7` holds **30 XSGD on both chains**.

Three traps worth knowing before you write any signing code:

1. **`version()` reverts on both chains**, as do `DOMAIN_SEPARATOR()` and `eip712Domain()`.
   Calling them at startup crashes the service. The version string comes from
   `challenge.extra.version` and nowhere else.
2. **6 decimals.** `"5000000"` is 5 XSGD. An 18-decimal assumption mis-encodes by 10¹² and
   the signature then verifies against the wrong value — silently.
3. **A `null` constant must make you refuse, never default.** Mainnet's `version` and
   settlement recipient are genuinely unknown until A18 fetches the production 402.

Money is always a **base-unit decimal string**, never a JSON number. Addresses are EIP-55 in
JSON but **compared lowercased**. See [api-contracts §0](docs/api-contracts.md); the
conventions are implemented once in `packages/contracts/src/validation.ts` — do not
reimplement them.

## Error envelope

Every service, every non-2xx:

```json
{ "error": { "code": "MANDATE_NOT_FOUND", "message": "…", "requestId": "3f6c…", "retryable": false } }
```

chain-gateway codes: `BAD_REQUEST` · `UNSUPPORTED_CHAIN` · `MANDATE_NOT_FOUND` ·
`TX_NOT_FOUND` · `RPC_FAILED` (502, retryable) · `RPC_TIMEOUT` (504, retryable) ·
`CHAIN_NOT_CONFIGURED` · `NOT_FOUND` · `TOKEN_DECIMALS_INVALID` · `X402_MALFORMED`

An RPC timeout **never** surfaces as a policy refusal — a judge reads that as a false
security claim.

### Never commit

A private key, a seed phrase, the keystore password, a full KMS key id, a raw signature,
typed-data message contents, a PAN, or a card iframe URL. `.gitignore` blocks `.env`,
`*.key`, `*.pem`, `keystore/` and `.aws/` as a backstop, but it is a backstop, not a policy.
