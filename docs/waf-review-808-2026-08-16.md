## Prioritized findings

### Critical
None. Isolation and custody invariants verified by deployed probe, not by design intent.

### High

**H1 — SEC02-BP03/BP05: Operator uses unrotated, long-lived static access keys; no MFA.**
- Evidence: `~/.aws/credentials` profile `straitsx` (static keys, created 2026-08-15); all
  applies ran as the user rather than the `straitsx-888-deployer` role intended by
  `scripts/setup-iam-roles.sh` guard flow. MFA virtual device created but not activated.
- Impact: a leaked key is an unrestricted control-plane compromise; no step-up auth.
- Remediation (smallest safe): activate MFA (2 consecutive TOTP codes), rotate the two keys,
  attach a policy to the user that requires `sts:AssumeRole` to the deployer role for
  terraform work, delete keys from credentials file afterward.
- Verification: console/key rotation completed; one `aws sts get-caller-identity` as role.

**H2 — REL07-BP02 / PERF05-BP03/04: No autoscaling and no load test for A/B services.**
- Evidence: all services pinned `desiredCount = 1` (no `aws_appautoscaling_target`,
  no CPU/memory alarms); only `ServiceRunningCount` alarms exist.
- Impact: demand spike at the demo degrades all tenancy-bearing services simultaneously.
- Remediation: application autoscaling on `ECSServiceAverageCPUUtilization` target 60–70%;
  then a load test (e.g. one-off tsx script hitting policy/ledger) to evidence scaling
  behavior — checklist requires alarm-behavior evidence, not just configuration.
- Verification: observed `runningCount` increases under test load; alarm fires.

**H3 — SEC04-BP02/BP03: Logs exist but are not aggregated/monitored.**
- Evidence: CloudTrail (bootstrap `audit.tf`), CW log groups `/ecs/straitsx-module-ab/*`,
  `/ecs/straitsx-module-c`, ALB access logs to `straitsx-888-…-alb-logs` prefix
  `straitsx-888`; no log subscription, no cross-log correlation, no retention policies set.
- Impact: post-incident forensics possible only ad hoc; drift/noise invisible.
- Remediation: (1) set retention 30–90 d on the three log groups; (2) subscribe CloudTrail
  + stop-event stream into an Athena/Grafana or at minimum a second ops SNS; (3) alarm on
  `TaskFailedToStart` count > 0 (EventBridge rule already routes stops — add the metric
  alarm for failed starts).
- Verification: log subscription delivering sampled events; alarm fires on forced stop.

### Medium

**M1 — OPS08-BP02/03: No dashboards.**
- Service/CPU/memory metrics available but unused; create one CloudWatch dashboard
  (service counts, CPU, signer health, probe PASS line).
- Evidence: no dashboard in account; alarms only.

**M2 — REL13-BP01/04 / REL09-BP02: RTO/RPO undefined; restore untested.**
- State bucket versioning is enabled (`bootstrap/main.tf` `versioning_configuration`) but no
  restore rehearsal exists; app runtime state is stateless (Cloud Map + fixed desiredCount)
  so restore applies mainly to TF state and the bucket — state restore should be rehearsed
  once and documented (RTO target ≤ 15 min).
- Evidence: terraform state present in S3, key `bootstrap/terraform.tfstate` (+ module
  stacks); no DR tests in repo.

**M3 — REL06-BP03/04 / PERF02: No CPU/memory alarms and no utilization visibility.**
- Add `ECSServiceAverageCPUUtilization` and `MemoryUtilization` alarms for the 4 A/B
  services and orchestrator/fixture, routing to the ops SNS.
- Evidence: only `ServiceRunningCount` alarm exists (module-ab `main.tf:494+`).

**M4 — COST04/REL09-SUS04: No lifecycle/retention policies.**
- CW log groups hold data indefinitely by default; ALB logs accumulate in S3 without
  lifecycle. Set transition/expiration (e.g. 90 d) and CW retention 30–90 d.
- Evidence: AWS default retention on all groups; no `aws_s3_bucket_lifecycle_configuration`.

**M5 — SEC10-BP02: No incident response drill or playbook run.**
- Playbook fragments live in docs; there is no documented, rehearsed IR sequence for
  "signer key suspected compromise" or "paying wallet drained" — the highest-impact
  incidents for this workload.
- Remediation: write a 1-page IR runbook (freeze signer, revoke grants, rotate key,
  notify ops SNS), walk it once.

**M6 — Internal token secrecy in logs.**
- `INTERNAL_TOKEN` provided Via secretsmanager at runtime (good). Ensure
  `execution_iam` never logs it (the services' log output seen in CW contains request
  logs only, but no test asserts token absence) — add a log assertion to the probe.
- Evidence: probe output PASS; signer log sample shows only req/res lines.
